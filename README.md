# ロト統計アナライザー

ロト6・ロト7の当せん番号を貼り付けて、**① 各数字の出現回数・出現率**と
**② 条件別の出現確率（引っ張り／連続／末尾同一 ほか）**を集計し、
頻度帯に沿った買い目を作る1ファイル構成のWebアプリです。

iOS Safari / ホーム画面へ追加したPWAでの利用を主対象にしつつ、Android Chromeでも動作します。

現在のバージョン: **v1.51**（`VERSION` を参照）

## ファイル構成

| ファイル | 役割 |
| - | - |
| `index.html` | アプリ本体（HTML / CSS / JavaScript を1ファイルに同梱） |
| `manifest.webmanifest` | PWA マニフェスト |
| `sw.js` | Service Worker（オフライン動作・バージョン別キャッシュ） |
| `icon.svg` | アイコン |
| `tools/test_app.js` | アプリ本体のテスト（ブラウザ・ネットワーク不要） |
| `VERSION` | 現在のバージョン番号 |
| `CHANGELOG.md` | 変更履歴とバージョン採番ルール |
| `CLAUDE.md` | 作業上の決まりごと |

`index.html` 単体でもそのまま動きます（PWA機能のみ無効）。

## 使い方

1. **データ**タブに当せん番号を取り込みます。
   当せん番号の一覧ページをブラウザで開いて**ページ全体をコピーし、そのまま貼り付けて「取り込む」**だけです。
   取り込みは常に追加で、同じ回は重複しません。
   - 月ごとに区切られた一覧表 … その月の全回がまとめて入ります。月を切り替えて繰り返せば過去分も集まります
   - 回ごとに1行の一覧表（`第2139回 2026/9/21 03 06 23 34 36 43 29 1 4億5,134万円 0円` のような形）
     … タブ区切り・スペース区切り・セルごとに改行される形のいずれも読めます
   - 賞金額・口数・キャリーオーバーの数字は取り込みません
   - 対応例: `第1900回 2026年5月2日 03 11 19 24 35 41 (07)`
   - 対応例: `1900,2026/05/02,3,11,19,24,35,41,7`
   - 取り込んだデータは端末のブラウザ内（localStorage）にだけ保存されます
2. **出現率**タブ … ①。出現回数別のまとめ（「出現回数4回 : 3個」形式）、数字別一覧、頻度帯の内訳。
3. **条件確率**タブ … ②。引っ張り・連続・末尾同一・合計値・奇数偶数・頻度帯の組み合わせ。
4. **予想**タブ … 頻度帯ごとの個数を決めて買い目を生成。
   気に入らない口は「この口だけ作り直す」で、他の口を残したまま選び直せます。
   同じタブの「この予想の作り方」に手順を書いてあります。

## 集計ルール

- 集計対象は「最新回から遡って指定回数分」（12/24/36/50/100/全件から選択）。
- 出現率 = 対象期間内の出現回数 ÷ 対象回数。本数字の理論値はロト6で 6/43、ロト7で 7/37。
- 引っ張り = その回の本数字のうち、直前回の本数字に含まれていた個数（設定で直前回のボーナスも対象にできます）。
- 連続数字 = 昇順に並べて差が1の並び。3連続は「2連続2組」とは別区分で数えます。
- 末尾同一 = 1の位が同じ数字のグループ。3個一致は2個一致とは別区分で数えます。
- 頻度帯 = 対象期間の本数字の出現回数を、理論期待値 ± 標準偏差の半分を境目として
  加熱帯・標準帯・低頻度帯の3つに分けたもの。予想はこの帯ごとの個数で組み立てます。
  各回が帯から何個ずつ出ていたかを数え、その実績から構成を抽せんします。
  このとき各回の帯は**その回より前のデータだけ**で決めます。その回自身を含めると、
  当せん番号は自分で出現回数を1増やすぶん必ず上の帯へ押し上げられ、加熱帯が1個ぶん水増しされるためです。

## テスト

```
node tools/test_app.js
```

`index.html` の `<script>` を隔離環境で実行し、統計の集計値・予想の生成・各形式の貼り付け取り込み・
頻度帯の分類と構成・1口ずつの作り直し・3か所のバージョンの一致・CSSの決まりごとを検査します（94項目）。
ブラウザもネットワークも使いません。GitHub Actions でも push のたびに実行します。

## バージョン管理

`VERSION` / `index.html` の `APP_VERSION` / `sw.js` の `APP_VERSION` を同じ値に更新し、
`CHANGELOG.md` に追記してから `git tag v<バージョン>` を打ちます。
採番ルールは `CHANGELOG.md` を参照してください。

## 注意

宝くじの抽せんは毎回独立した事象です。本アプリの統計・予想は過去傾向を可視化するものであり、
当せんを保証するものではありません。購入は自己責任でお願いします。
