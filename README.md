# ロト統計アナライザー

ロト6・ロト7の当せん番号を貼り付けて、**① 各数字の出現回数・出現率**と
**② 条件別の出現確率（引っ張り／連続／末尾同一 ほか）**を集計し、
その分布に沿った買い目を生成する1ファイル構成のWebアプリです。

iOS Safari / ホーム画面へ追加したPWAでの利用を主対象にしつつ、Android Chromeでも動作します。

現在のバージョン: **v1.13**（`VERSION` を参照）

## ファイル構成

| ファイル | 役割 |
| - | - |
| `index.html` | アプリ本体（HTML / CSS / JavaScript を1ファイルに同梱） |
| `manifest.webmanifest` | PWA マニフェスト |
| `sw.js` | Service Worker（オフライン動作・バージョン別キャッシュ） |
| `icon.svg` | アイコン |
| `tools/fetch_mizuho.js` | みずほ銀行から当せん番号を取得してJSONに保存するスクリプト |
| `tools/test_app.js` | アプリ本体のテスト（ブラウザ・ネットワーク不要） |
| `tools/test_parse.js` | 解析処理のテスト（ネットワーク不要） |
| `CLAUDE.md` | 作業上の決まりごと |
| `tools/testdata/` | みずほのページ構成を再現したテスト用HTML |
| `.github/workflows/fetch-loto.yml` | 上記を毎日実行して `data/` に自動コミットするワークフロー |
| `data/` | 取得済みの当せん番号（`loto6.json` / `loto7.json`） |
| `VERSION` | 現在のバージョン番号 |
| `CHANGELOG.md` | 変更履歴とバージョン採番ルール |

`index.html` 単体でもそのまま動きます（PWA機能のみ無効）。

## 使い方

1. **データ**タブで「最新データを取得して追加」を押すか、当せん番号を貼り付けて「解析して置き換え」。最新回から24回分以上あると分析が安定します。
   - 対応例: `第1900回 2024年5月2日 03 11 19 24 35 41 (07)`
   - 対応例: `1900,2024/05/02,3,11,19,24,35,41,7`
   - 対応例: `03 11 19 24 35 41 07`（数字のみ。並び順は画面の設定で指定）
   - 取り込んだデータは端末のブラウザ内（localStorage）にだけ保存されます。
2. **出現率**タブ … ①。出現回数別のまとめ（「出現回数4回 : 3個」形式）と数字別一覧。
3. **条件確率**タブ … ②。引っ張り・連続・末尾同一・合計値・奇数偶数の出現確率と回別明細。
4. **予想**タブ … 重み付けモードと適用条件を選んで買い目を生成。

## 当せん番号の自動取得

みずほ銀行のページをブラウザから直接 `fetch()` することは **CORS制限でできません**
（みずほ側が `Access-Control-Allow-Origin` を返さないため、iOS SafariでもPWAでもブロックされます）。
そのため次の流れにしています。

```
GitHub Actions（1日1回）
  → tools/fetch_mizuho.js がみずほの「抽せん数字一覧表」を取得・解析
  → data/loto6.json / data/loto7.json を更新してコミット
アプリ
  → raw.githubusercontent.com（CORS許可あり）または同一オリジンの ./data/ からJSONを取得
```

取得元のページは次の2つです。

- ロト6: `https://www.mizuhobank.co.jp/takarakuji/check/loto/loto6/index.html`
- ロト7: `https://www.mizuhobank.co.jp/takarakuji/check/loto/loto7/index.html`

1か月分ずつの掲載で、過去の月は `?year=2026&month=8` を付けて参照します。
当月ページを起点に年月を1か月ずつ遡り、新しい回が無い月が2回続いたら打ち切ります。
既存の `data/*.json` を読んでから取得するので、**初回だけ過去をまとめて取り込み、
以降の定期実行は当月ページの1リクエストで終わります**
（初回はロト6で20か月ほど、ロト7で30か月ほど遡ります。1.2秒間隔で30〜40秒程度）。

### 有効にする手順

1. リポジトリの Settings → Actions → General → Workflow permissions で
   **Read and write permissions** を有効にします（`data/` への自動コミットに必要）。
2. ワークフローは `push` でも動くので、作業ブランチに push すれば実行されます。
   実行されたブランチの `data/` にコミットされます。
   （`schedule` と `workflow_dispatch` は既定ブランチのワークフローしか動かない仕様です。
   毎日の自動実行をしたい場合は既定ブランチに入れてください。）
3. Actions の実行結果で `data/loto6.json` と `data/loto7.json` が作られたことを確認します。
4. アプリの「データ」タブで「最新データを取得して追加」を押します。
   取得元の欄は**空欄のままでOK**です（このページと同じ場所の `data/` を読みます）。
   GitHub Pages で同じブランチを公開していれば、これだけで最新回と過去分がまとめて入ります。
   別の場所に置いたJSONを読むときだけ、`https://raw.githubusercontent.com/ユーザー名/loto/ブランチ名/data`
   のように指定します。**みずほのURLを入れる欄ではありません。**

### 手元で実行する

```
node tools/fetch_mizuho.js both data 120
```

引数は順に「対象（both / loto6 / loto7）」「出力ディレクトリ」「保持件数」です。
環境変数で挙動を変えられます。

| 環境変数 | 内容 |
| - | - |
| `LOTO_MONTHS` | 何か月前まで遡るか（既定 30） |
| `LOTO_URL` | 起点URLの差し替え |
| `LOTO_URLS` | 取得するURLをカンマ区切りで直接指定（月送りせずこの一覧だけを読む） |
| `LOTO_SLEEP` | リクエスト間隔のミリ秒（既定 1200。テスト用。むやみに小さくしない） |
| `LOTO_FILE` | 保存済みHTMLを解析（ネットワーク不要。動作確認用） |
| `LOTO_DEBUG` | `1` で詳細ログ |

取得できた件数が0だったり、数字の個数・範囲・重複が不正だった場合はファイルを書かずに
終了コード1で失敗します（壊れたデータがコミットされないようにするため）。

### テスト

```
node tools/test_app.js
LOTO_SLEEP=0 node tools/test_parse.js
```

`tools/test_app.js` は `index.html` の `<script>` を隔離環境で実行し、
統計の集計値・予想の生成・貼り付け取り込み・自動取得の挙動・
3か所のバージョンの一致・CSSの決まりごとを検査します（34項目）。

`tools/test_parse.js` は、`tools/testdata/` にある、みずほの「抽せん数字一覧表」の構成を再現したHTML
（回別・抽せん日・本数字・ボーナス数字・等級別の口数と金額・販売実績額・キャリーオーバー、
および「2026年9月分　（第2134回〜第2139回）」の見出し）を使って、
次を確認します。ネットワークは使いません。ワークフローも取得前にこれを実行します。

- 回号・抽せん日・本数字・ボーナス数字を正しく抜き出せること（ロト6・ロト7とも）
- 賞金額や口数の数字を当せん番号として拾わないこと
- 見出しの「第2134回〜第2139回」を抽せん結果として取り込まないこと
- Shift_JISの自動判別と全角数字の変換
- 月別ページのURLを `index.html?year=2026&month=8` の形で正しく組み立てること
- 月を遡って取得し、新しい回が無い月が2回続いたら打ち切ること
- 不正なデータを検証で弾けること

### 未確認の点

ページ構成とURL仕様は実物にもとづいて検証済みですが、
**実際にみずほのサイトへHTTPで接続する部分は未検証**です（開発環境から外部へ接続できないため）。
初回は Actions の手動実行、またはネットワークのある端末で
`LOTO_DEBUG=1 node tools/fetch_mizuho.js loto6 data 30` を実行し、
何件取得できたかを確認してください。
うまくいかない場合は、取得したいURLを `LOTO_URLS` にカンマ区切りで直接指定できます。

みずほ側のページ構成が変わると解析に失敗します。その場合は
`LOTO_DEBUG=1` を付けて実行し、`tools/fetch_mizuho.js` の `parseBlock()` を調整してください。
なお取得先に負荷をかけないよう、リクエスト間隔を空け、実行は1日1回にとどめています。

## 集計ルール

- 集計対象は「最新回から遡って指定回数分」（既定24回、12/24/36/50/100/全件から選択）。
- 出現率 = 対象期間内の出現回数 ÷ 対象回数。本数字の理論値はロト6で 6/43、ロト7で 7/37。
- 引っ張り = その回の本数字のうち、直前回の本数字に含まれていた個数（設定で直前回のボーナスも対象にできます）。
- 連続数字 = 昇順に並べて差が1の並び。3連続は「2連続2組」とは別区分で数えます。
- 末尾同一 = 1の位が同じ数字のグループ。3個一致は2個一致とは別区分で数えます。

## バージョン管理

`VERSION` / `index.html` の `APP_VERSION` / `sw.js` の `APP_VERSION` を同じ値に更新し、
`CHANGELOG.md` に追記してから `git tag v<バージョン>` を打ちます。採番ルールは `CHANGELOG.md` を参照してください。

## 注意

宝くじの抽せんは毎回独立した事象です。本アプリの統計・予想は過去傾向を可視化するものであり、
当せんを保証するものではありません。購入は自己責任でお願いします。
